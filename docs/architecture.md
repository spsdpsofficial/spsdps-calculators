# Architecture

Modular monolith, static-first: one Next.js app, six categories, one folder per tool, calculations in the browser, no backend/DB.

## Pinned versions (installed 2026-11-11)
next 16.4.6, react / react-dom 19.3.1, tailwindcss + @tailwindcss/postcss 4.3.5, eslint 9.39.5, eslint-config-next 16.4.6, vitest 5.1.0, pdf-lib 1.17.1 (PDF tools only), Node >= 22. Exact versions are locked in `package.json` and `package-lock.json`. Only the integrator upgrades dependencies.

## Ownership (from the blueprint)
LLM A finance, B salary-tax, C daily-life, D health, E business, F utilities: each only `features/<cat>/**` and `app/<cat>/**`. Integrator owns `app/layout.js`, `app/page.js`, `globals.css`, `components/**`, `lib/**`, package files, config, CI.

## Key rules
- Pure calculation functions; validation separate; UI reuses shared components.
- `lib/tools/catalogue.js` is the single source of truth for routes, nav, sitemap and links.
- Server Components for static content; Client Components only for interactive parts.
- Tool pages are generated by `components/calculator/ToolPage.js` so every page has the same SEO structure.

## Tool engine
Most tools are a `spec.js` (fields + `run`) rendered by `components/calculator/FormCalculator.js`, validated by `lib/forms/validateFields.js`. Tools that need files, canvas or free text (unit converter, EMI schedule, utilities) have their own component. Date-dependent tools set `usesToday` so the server-rendered HTML never contains a date that differs from the browser's.
